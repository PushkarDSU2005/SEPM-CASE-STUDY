# Human Validation and Requirements Analysis

## 1. Purpose

The purpose of this document is to review and validate the requirements generated by ChatGPT for the Student Task Management System.

The review identifies incomplete requirements, unconfirmed assumptions, missing information and potential project risks.

## 2. Validation Approach

The AI-generated requirements were reviewed using five criteria:

- Accuracy: Does the requirement match the original project description?
- Completeness: Is important information missing?
- Relevance: Is the requirement relevant to the project?
- Feasibility: Can it be implemented within the project scope?
- Clarity: Is the requirement understandable and testable?

Four validation decisions were used:

- Accept: The item is correct and relevant.
- Modify: The item needs correction or additional detail.
- Reject: The item is incorrect or outside the project scope.
- Clarify: More information is required before approval.

## 4. Human-Identified Gaps

The review identified the following unresolved questions:

1. What information should be stored for each academic task?
2. Can students access only their own tasks?
3. What should happen when a student deletes a task?
4. What is the exact definition of an upcoming task?
5. How should the system classify an overdue task?
6. What registration fields and login rules should be used?
7. What are the expected security, usability and compatibility requirements?

## 6. Proposed Quality Requirements

The original AI output did not establish measurable non-functional requirements. The following are proposed project-level expectations for implementation and testing, not requirements confirmed by the original request:

- Usability: The interface should be simple and understandable for students.
- Compatibility: The application should work in the selected modern desktop browser.
- Data handling: Task information should remain available after a page refresh during the demonstration.
- Maintainability: HTML, CSS and JavaScript code should be organized and understandable.
- Security: Authentication and user data handling limitations should be documented honestly.

## 7. Confirmed Constraints

- Application: Student Task Management System.
- Technology stack: HTML, CSS, JavaScript, Git and GitHub.
- Methodology: Agile Scrum.
- Team size: One.
- Testing approaches: Functional, negative and automated testing.

Budget, hosting, deployment environment and regulatory constraints have not been established.

## 8. Human-Validated Assumptions

The following assumptions remain subject to confirmation:

- Students manage their own academic tasks.
- Task deadlines are used to classify upcoming and overdue tasks.
- Students access the system through a web browser.

These assumptions will be documented and checked during implementation.

## 9. Identified Risks and Mitigation

| Risk | Potential impact | Proposed mitigation |
|---|---|---|
| Ambiguous task fields | Inconsistent implementation | Define required task fields before coding. |
| Undefined authentication behavior | Login and registration errors | Define and test authentication behavior. |
| Unclear deadline rules | Incorrect upcoming and overdue classification | Establish deadline comparison rules. |
| Undefined status behavior | Inconsistent task states | Use only the three approved statuses. |
| Missing quality requirements | Quality expectations may not be met | Establish practical project-level quality criteria. |
| Single-person team capacity | Limited time for development and testing | Prioritize essential features and use short development iterations. |
| AI-generated errors | Incorrect requirements or code may enter the application | Apply human review and functional testing before accepting AI-generated work. |

## 10. Conclusion

The human review found that the AI-generated functional requirements accurately represented the original project description. However, several details were incomplete or required clarification.

The review also identified unconfirmed assumptions, missing non-functional requirements and potential implementation risks.

This demonstrates that Generative AI can assist with requirements engineering, but human validation is necessary before AI-generated outputs are accepted as final project requirements.
